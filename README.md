## Overview

This repository documents my academic learning activities associated with participation in the second cohort of the **Global AI Compute Faculty Development Initiative**, held in Beijing in October 2026. Its purpose is to organize technical learning, document independently developed exercises, and support the transfer of knowledge into teaching, research, and reproducible experimentation.

The portfolio is a **work in progress**. Repository contents should be interpreted according to their stated authorship, provenance, and publication permissions. Inclusion of a resource does not imply that I authored it.

## Technical scope

- **AI computing systems:** computing foundations, accelerator software stacks, and AI system software.
- **High-performance operators:** operator implementation, fusion, attention-related computation, and performance analysis.
- **AI compilers and kernels:** compilation workflows, Triton programming, and kernel optimization.
- **Distributed AI:** distributed training and inference, communication, and scalability considerations.
- **Edge AI:** deployment constraints and system-level considerations for edge environments.
- **Performance engineering:** benchmarking methodology, reproducibility, and interpretation of measurements.

These topics describe the scope of the portfolio; they are not claims that every topic already has a completed original experiment.

## Learning-to-practice workflow

1. **Study:** identify the concepts and system assumptions of each module.
2. **Implement:** develop or adapt exercises with clearly stated authorship and dependencies.
3. **Evaluate:** record hardware, software versions, input sizes, metrics, and limitations.
4. **Reflect:** summarize technical lessons and potential applications to teaching and research.
5. **Share responsibly:** publish only material whose disclosure and redistribution are permitted.

## Reproducibility standards

When an original experiment is added, its documentation should include the objective, environment, installation commands, input data, execution steps, expected outputs, measurements, and known limitations. Performance comparisons should state the hardware and measurement methodology; results should not be generalized beyond the tested conditions.
